Cyber Forensics Lab Project: 5 Security Controls Summary

Overview of the five security features implemented across this project for your laboratory submission.

1. Cryptographic File Hashing (SHA-256) Automatically calculates a unique 256-bit cryptographic digest as soon as any evidence file is uploaded. If a single byte of the file is altered, the hash changes completely (avalanche effect), immediately exposing evidence tampering.
2. Immutable Audit Logging (Chain of Custody) Maintains an append-only log of every interaction (Upload, View, Verify, Transfer). Records timestamp, officer name, action performed, and hash snapshot. In a production database, SQL triggers prohibit UPDATE and DELETE operations.
3. Role-Based Access Control (RBAC) Restricts permissions based on user role to enforce least-privilege: Lead Investigators can ingest new evidence and transfer custody; Forensic Analysts can view and verify hashes; Auditors have read-only access to audit logs.
4. Input Validation & File Sanitization Strips path traversal sequences like ../, removes dangerous script characters, and isolates uploaded files outside the web root to block Remote Code Execution (RCE) and directory climbing attacks.
5. Time-Based One-Time Password (TOTP) 2FA Protects investigator accounts against stolen credentials by requiring a rolling 6-digit authentication token (e.g., Google Authenticator / Authy) before allowing access to evidence.
